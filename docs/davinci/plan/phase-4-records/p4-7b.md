# P4-7b — Facade switch — Relief projection still live

**Not closed.** `lint_jsx` drives the markup-facade rules over S2. `lint_sfc`
drives 38 proven rules over S2, and `MarkupDocumentInner::Relief` / `MarkupDocument::from_jsx` are
still in the tree. The phase box stays open.

## What landed

- `Linter::lint_jsx` projects each render root through P2-16
  (`S2Markup::from_projected_root`) and runs every markup rule on that view.
  `jsx_needs_lowering` only partitions the walk so a rule runs once. A root
  the projection refuses (`UnsupportedElement`, comments, compound
  expressions, …) keeps the lowered Relief document, so a conditional
  fragment the projection will not admit still lints.
- Element-shaped rules no longer merge the lowering's diagnostics. The OXC
  parse set is unchanged; list-shaped and legacy rules still merge it.
- `LintDocumentKind::s1_input_dialect` maps `VueSfc` / `MarkupFragment` to
  the Vue template surface and `ScriptModule` to JSX. `S1InputDialect::from_template_lang`
  selects pug. Astro and Svelte stay unmapped.
- `patina_jsx_markup_one_root` measures the S2 visit (the list/branch
  partition stays outside the window). Re-measured allocs: JSX **0** (held),
  template `patina_s2_markup_one_root` **7** (held).

## Why the remaining SFC rules have not switched

The remaining SFC markup rules still run through `Rule` on the Relief tree.
Driving them through `MarkupRule` on S2 changes diagnostics, which TS-9
forbids:

- `vue/permitted-contents` reads `template_skeleton` (authored reparse) from
  `run_on_template`, not `skeleton` of the S2 document.
- `vue/no-bare-strings-in-template` reports the same span and text, but the
  facade emits that diagnostic before `html/deprecated-attr`. Relief emits the
  attribute diagnostics first.

Those bodies live under `rules/`, outside this lane. P4-8 owns making one
body serve both syntaxes.

## What projection remains

- `MarkupDocumentInner::Relief` and `MarkupDocument::new`, used by the
  content-model skeleton (`html_content_model`, lane I), `heading_levels`'
  `run_on_template`, the JSX refusal fallback, and the TS-25 differential.
- `MarkupDocument::from_jsx` and the OXC element projection, used by the
  facade's direct-JSX unit tests. `lint_jsx` does not call it.
- The legacy JSX fallback (`legacy_keep_mask`) for the 208 rules not on the
  facade.

`grep -n "MarkupDocumentInner::Relief\|fn from_jsx" crates/vize_patina/src`
is not empty.

## Authored bindings and accessibility exceptions (2026-09-26)

Six more rules now use the same S2 dispatch, for 38 admitted rules:

- `a11y/no-access-key`
- `a11y/no-autofocus`
- `vue/require-v-for-key`
- `vapor/prefer-static-class`
- `a11y/no-redundant-roles`
- `a11y/interactive-supports-focus`

Static argument checks preserve Vue's exact spelling and ignore dynamic
arguments; JSX keeps its existing normalized casing. Authored argument and
structural directive ranges come from the retained S1 attributes. In particular,
empty or malformed `v-for` attributes still produce the old key diagnostic even
when lowering creates no list op, and `v-pre` attributes stay frozen. The class
rule shares its complete diagnostic and edit contract with the retained path.

The redundant-role rule shares its stylesheet exception, including nested
media/supports/layer rules, bound literal classes and first-attribute behavior.
A separate SFC comparison forces the legacy rule path and checks full diagnostics
against the facade for inline CSS, mismatching selectors, external styles and
non-CSS languages. The focus rule shares its document-wide controller discovery
and checks, so controllers before or after a listbox and inside control scopes
have the same effect. Its document hook retains the two element passes that the
old template hook used; JSX retains its existing per-element behavior.

Validation includes the complete diagnostic/fix battery over committed fixtures
and all 90 construct templates, additional dynamic-argument/Unicode/CRLF
witnesses, the stylesheet comparison, and the route canary for every admitted
rule. The full Patina library suite and test-target Clippy are required for this
slice. `vue/permitted-contents`, `vue/no-bare-strings-in-template`, the Relief
fallbacks and the P4-7b phase exit remain open.
